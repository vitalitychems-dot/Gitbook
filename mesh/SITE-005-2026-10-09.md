## Recommendation

Hybrid. The web artifact builds to static files. The API is a separate Node process. The current API tree does not serve `artifacts/tessera/dist/public`.

A static host can serve the web files. The API still needs its own runtime. One machine can run both, and the current scripts already start them separately.

## Build

- Web: `artifacts/tessera/package.json` script `build` runs `vite build --config vite.config.ts`.
- Web output: `artifacts/tessera/dist/public`.
- Web config requires `PORT` and `BASE_PATH` before the config loads. `REPL_ID` only adds the Replit serve-mode plugins when the Vite command is `serve`.
- API: `artifacts/api-server/package.json` script `build` runs `node ./build.mjs`.
- Root: `package.json` script `build` runs `node scripts/build-unified.mjs`.

## Runtime

- API start: `node --enable-source-maps ./dist/index.mjs` from `artifacts/api-server`.
- API listen: `PORT` is required. The process throws if `PORT` is missing or not a positive number.
- Web preview in this repo: `vite preview --config vite.config.ts --host 0.0.0.0`. That command loads the same config, so it also requires `PORT` and `BASE_PATH`.
- Health path: `GET /api/healthz`. The handler in `artifacts/api-server/src/routes/health.ts` is `GET /healthz` and returns `{ status: "ok" }`. `artifacts/api-server/src/app.ts` mounts the API router at `/api`.

## Non-secret environment names

- `PORT`
- `BASE_PATH`
- `REPL_ID` (gates serve-mode plugins only)

No secret value is in this report.
